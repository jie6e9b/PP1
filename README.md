# Учебный проект на Python
Этот репозиторий содержит набор модулей для работы с финансовыми транзакциями: фильтрация, сортировка, маскирование конфиденциальных данных и отображение информации.

## ▎Модули

### ▎1. `processing.py` - Обработка транзакций
Модуль предоставляет функции для фильтрации и сортировки списков транзакций.

Основные функции:
- `filter_by_state(transactions, state)` - фильтрация транзакций по статусу
- `sort_by_date(list_dict, revers=True)` - сортировка транзакций по дате

### ▎2. `masks.py` - Маскирование данных

Модуль содержит функции для маскирования конфиденциальных данных в финансовых транзакциях, таких как номера карт и счетов.

Основные функции:

- `mask_card_number(card_number)` - маскирование номера карты (XXXX XX ** XXXX)
- `mask_account_number(account_number)` - маскирование номера счета (**XXXX)

### ▎3. `widget.py` - Отображение транзакций

Модуль предоставляет функции для форматирования и отображения информации о транзакциях в удобном для пользователя виде.

Основные функции:

- `format_transaction(transaction)` - форматирование данных транзакции
- `display_transactions(transactions, limit=5)` - отображение списка транзакций с ограничением по количеству

### ▎4. `generators.py` - Генераторы 

Основные функции:

- `filter_by_currency` - функция фильтрует список транзакций по указанной валюте и возвращает итератор. 
  Параметры: * transactions: список словарей, представляющих транзакции
             * currency: строка с кодом валюты для фильтрации (например, "USD")
  Возвращает: Итератор, который последовательно выдает транзакции с указанной валютой.

- `transaction_descriptions` - генератор, который последовательно возвращает описания транзакций. 
   Параметры: transactions: список словарей с транзакциями 
   Возвращает: итератор, который последовательно выдает строки с описанием каждой транзакции.

- `card_number_generator` - генератор номеров банковских карт в формате XXXX XXXX XXXX XXXX.
   Параметры: start: начальное значение диапазона (от 1 до 9999999999999999)
              end: конечное значение диапазона (от start до 9999999999999999)
   Возвращает: итератор, который последовательно выдает строки с номерами карт в формате XXXX XXXX XXXX XXXX.

### ▎5. `decorators.py` - Декоратор логирования

Модуль предоставляет декоратор log, который позволяет логировать выполнение функций. 
Декоратор записывает информацию об успешном выполнении функции или о возникших ошибках 
в указанный файл или в стандартный вывод.

Основные функции:

- `@log()` логирование в консоль

- `@log(filename="logs.txt")` логирование в файл

- `filename` (опционально): Имя файла для записи логов. Если не указан, логи выводятся в консоль.

Логирует успешное выполнение функции с сообщением {имя_функции} ok.
В случае ошибки логирует имя функции, тип ошибки и входные параметры.
Автоматически закрывает файл после записи логов.
Сохраняет метаданные оригинальной функции (имя, докстринг и т.д.).
Пробрасывает исключения дальше, чтобы не нарушать нормальный поток выполнения программы.

Пример вывода при успешном выполнении:
example_function ok
При ошибке: risky_function error: ZeroDivisionError. Inputs: (1, 0), {} 
Типизация - модуль полностью типизирован с использованием аннотаций типов Python, что обеспечивает совместимость с инструментами статического анализа кода, такими как mypy.

### ▎6. `utils.py` - утилиты

Основные функции:
- `read_json_finance(path: str) -> list` - читает JSON-файл с финансовыми транзакциями и возвращает их в виде списка словарей
- `returns_transaction_amount(transaction: dict) -> Optional[float]` - Возвращает сумму транзакции в рублях. Если валюта не рубли, конвертирует через API обмена валют.

## ▎Тестирование

### ▎5. Модуль тестирования `test_decorators`

Модуль test_decorators содержит набор тестов для проверки функциональности декоратора log. 
Тесты проверяют корректность логирования как при успешном выполнении функций, так и при 
возникновении ошибок, с выводом в консоль и с записью в файл.

Структура тестов
Модуль содержит четыре тестовые функции:

1. test_log_success_console - проверяет логирование успешного выполнения функции в консоль
2. test_log_error_console - проверяет логирование ошибки в консоль
3. test_log_success_file - проверяет логирование успешного выполнения функции в файл
4. test_log_error_file - проверяет логирование ошибки в файл

Методика тестирования

- Для перехвата вывода в консоль используется фикстура capsys из pytest
- Для тестирования записи в файл создаются временные файлы, которые удаляются после завершения теста
- Тесты с ошибками используют контекстный менеджер pytest.raises для проверки, что исключения корректно пробрасываются

Запуск тестов
pytest test_decorators.py -v

Примеры тестовых сценариев

Успешное выполнение с выводом в консоль
Тест создает декорированную функцию сложения, вызывает ее и проверяет, что:
- Функция возвращает правильный результат (3)
- В консоль выводится сообщение "add ok"

Обработка ошибки с выводом в консоль
Тест создает декорированную функцию деления, вызывает ее с делителем 0 и проверяет, что:
- Исключение ZeroDivisionError корректно пробрасывается
- В консоль выводится сообщение об ошибке с информацией о входных параметрах

Успешное выполнение с записью в файл
Тест создает декорированную функцию умножения, вызывает ее и проверяет, что:
- Функция возвращает правильный результат (6)
- В файл записывается сообщение "multiply ok"

Обработка ошибки с записью в файл
Тест создает декорированную функцию доступа к элементу списка, вызывает ее с пустым списком и проверяет, что:
- Исключение IndexError корректно пробрасывается
- В файл записывается сообщение об ошибке с информацией о входных параметрах

Очистка ресурсов
Все временные файлы, созданные во время тестирования, автоматически удаляются после завершения тестов. 

### ▎6. Модуль тестирования `test_utils`

Тесты функции `read_json_finance(path: str) -> list`:

1. `test_valid_json_file()` - тестирует функцию `read_json_finance` с корректным JSON-файлом. Создает временный JSON-файл с тестовыми данными, вызывает функцию read_json_finance и проверяет, что она корректно считывает и возвращает данные из файла. После завершения теста временный файл удаляется. 

2. `test_nonexistent_file()` - тестирует функцию read_json_finance с несуществующим файлом. Проверяет, что функция корректно обрабатывает ситуацию, когда указанный файл не существует: возвращает пустой список и выводит соответствующее сообщение об ошибке. Для проверки вывода в консоль используется перехват стандартного потока вывода.

Тесты функции`returns_transaction_amount(transaction: dict) -> Optional[float]` 

1. `test_transaction_in_rubles(mock_getenv: MagicMock, mock_load_dotenv: MagicMock, mock_exists: MagicMock)`  - проверяет корректность обработки транзакции в рублях. Функция должна просто вернуть сумму без конвертации,  и не должна обращаться к переменным окружения.

2. `test_transaction_in_foreign_currency(  mock_request: MagicMock, mock_getenv: MagicMock, mock_load_dotenv: MagicMock, mock_exists: MagicMock)` - проверяет корректность конвертации транзакции в иностранной валюте в рубли.  Функция должна получить API ключ из переменных окружения, выполнить запрос к API для получения курса валют и конвертировать сумму в рубли.


## ▎Система логирования

### ▎1. Система логирования `masks.py` 

В проекте реализована система логирования, которая записывает информацию о работе модуля маскирования данных в отдельные файлы. Логи разделены по уровням важности и сохраняются в директории logs.

▎Особенности системы логирования

- Раздельные файлы логов:
  - info_masks.log - содержит сообщения уровней INFO и WARNING
  - error_masks.log - содержит сообщения уровней ERROR и CRITICAL

- Формат логов:
YYYY-MM-DD HH:MM:SS,ms - masks.py - LEVEL - Сообщение
- Режим записи: файлы логов перезаписываются при каждом запуске приложения

▎Использование логгера

Логгер инициализируется автоматически при импорте модуля и используется для отслеживания следующих событий:

- Информационные сообщения о попытках маскирования данных
- Предупреждения при получении некорректных данных (неправильная длина, None)
- Ошибки при получении данных неподдерживаемого типа
- Успешное завершение операций маскирования

▎Пример логов
2023-11-15 14:23:45,123 - masks.py - INFO - Попытка маскировки номера карты: <class 'str'>
2023-11-15 14:23:45,125 - masks.py - INFO - Номер карты успешно замаскирован
2023-11-15 14:23:45,130 - masks.py - WARNING - Некорректная длина номера карты: 15
2023-11-15 14:23:45,135 - masks.py - ERROR - Неверный тип данных для номера счета: <class 'list'>
▎Настройка логгера

Логгер настраивается функцией setup_logger(), которая создает необходимую директорию для логов, устанавливает форматтеры и обработчики для разных уровней логирования.

Для использования логгера в других модулях достаточно импортировать переменную logger из основного модуля.
